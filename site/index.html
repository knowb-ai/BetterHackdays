01

Orientation

BetterHackdays is an open-source Hack Day room: it connects coding agents, matches people into teams, and turns pasted event text into a shared kickoff plan. The RFP Connector is the part of BetterHackdays that opens KnowB's project requests for proposals to outside builders.

Run the connector as an MCP server inside the agent you already use, or call the same functions over REST. Either way you can:

  • browse the approved public RFPs and the live public projects behind them;
  • check a new idea against the canonical idea catalogue, the open projects, and the knowb.run showcase;
  • send a refinement, an expression of interest, or an access request to a maintainer, with your identity verified by GitHub.

The connector is the source

This site explains and points. Every RFP read, comparison, and request happens in the connector, so answers are always current.

The catalogue stays canonical

Idea suggestions live in Cloud Builder Stack. The connector reads them live and never copies them here.

Requests stay private

Request details go to maintainers, not to a public issue, a feed, or this page.

02

Quickstart

You need Python 3.12, Git, and an MCP-capable agent such as Claude Code. Reading RFPs needs no account. Submitting a request needs a GitHub token for your own account, because the token is how the connector knows who you are.

  1. Clone and install

    git clone https://github.com/knowb-ai/BetterHackdays.git
cd BetterHackdays
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

  2. Connect your agent

    Pick your client. Run the command from the repository root so the paths resolve.

    claude mcp add betterhackdays \
  -e PYTHONPATH="$PWD" \
  -e DATABASE_URL="sqlite:///$PWD/betterhackdays.db" \
  -- "$PWD/.venv/bin/python" -m app.mcp_server
    {
  "mcpServers": {
    "betterhackdays": {
      "command": "/path/to/BetterHackdays/.venv/bin/python",
      "args": ["-m", "app.mcp_server"],
      "env": {
        "PYTHONPATH": "/path/to/BetterHackdays",
        "DATABASE_URL": "sqlite:////path/to/BetterHackdays/betterhackdays.db"
      }
    }
  }
}
    .venv/bin/uvicorn app.main:app --reload --port 8000
# in another terminal
curl -s "http://localhost:8000/rfps/search?q=inbox"

    Interactive API docs: http://localhost:8000/docs.

  3. Ask in plain language

    Your agent picks the right tool. Try:

    • “List the KnowB RFPs and group them by theme.”
    • “Compare MarkSweep and Subtracktor for a two-person weekend team.”
    • “Would a calendar-aware inbox triage idea qualify for the catalogue?”
    • “Draft an expression of interest for Underminer and show me the preview.”

  4. Add your identity, only to send requests

    Give the server a fine-grained GitHub token for your own account in GITHUB_TOKEN. Keep it in your client's local config or a secret manager, never in a repository or a chat message. The connector resolves your login from the token with GitHub; it never accepts a login you type.

04

Refine ideas

The idea catalogue lives in Cloud Builder Stack, and it stays there. The connector fetches it live each time and fails closed: if the catalogue cannot be read, you get an honest source_unavailable, never a stale copy.

  1. Fetchfetch_idea_catalogue

    Read suggestions live, filtered by query or section.

  2. Qualifyqualify_idea

    A deterministic check against the catalogue, open public projects, and the knowb.run showcase. Duplicates and showcased work come back not_eligible.

  3. Proposepropose_idea_catalogue_addition

    Previews by default. With submit, it opens a pull request to Cloud Builder Stack, only after a human-reviewed rationale, a named reviewer, and that repository's review rules all check out.

A proposal is a pull request, never a direct write. Cloud Builder Stack's maintainers merge or decline it.

05

Contributor requests

!

A request is not a grant.

Submitting a request never changes who can push to a repository. Access to any repository requires the owner's explicit approval, given by a person, outside the connector. No QR code, slug, match, or submitted form grants access on its own.

Request types

Request typeUse it toRequester needs on BetterHackdays
RFP Refinement Draft
refinement_draft		Suggest sharper scope, outcomes, or safety notes for an existing RFP brief.Read or higher
Expression of Interest
expression_of_interest		Tell the maintainers you want to work on an RFP, with no access asked for.Read or higher
Project Contribution Access Request
contribution_access_request		Ask to be considered for contributor access to the project behind an RFP.Read or higher
Work Elevation Request
work_elevation_request		Ask for elevated work on a project you already contribute to.Write, maintain, or admin

How a request travels

  1. 1
    Preview. Call preview_contributor_request with a type, an RFP ID, the scope you want, and a short message. Nothing is sent. Read the draft, and fix it if it is wrong.
  2. 2
    Submit. Call submit_contributor_request. The connector verifies your GitHub identity from your token and checks your permission on BetterHackdays. If either check fails you get unauthorized, and nothing leaves your machine.
  3. 3
    Route. The request is recorded privately and sent to the maintainers at ping@knowb.run. If mail is not configured, you get the complete addressed draft back, plainly marked not sent, to send yourself.
  4. 4
    Review. A repository owner reads it and decides. If they approve access, they send the GitHub invitation themselves. Track your own requests with list_contributor_requests.

Write requests the way you would write to a person: what you want to work on, why, and what you have built before. Leave out passwords, tokens, and private data.

06

Permission boundaries

The connector is built to be safe to hand to an agent. These rules are enforced in code and covered by the test suite.

Identity comes from GitHub, not from you
Request bodies and tool arguments never carry identity or role claims. The connector resolves your login from your token with the GitHub API and ignores any login or role that is typed in.
Exact permission, exact repository
Every write checks your live permission on the one repository it targets. Requests need read or higher on BetterHackdays; work elevation needs write or higher.
The bot's scope is checked too
Writes made through the KnowB GitHub App must fit the scopes that app was installed with, and only on an allowlist of public KnowB repositories.
Access grants are owner-only, and preview-only here
grant_repository_access only ever returns a dry run over MCP. Real invitations are sent by the repository owner, by hand.
Failures close, never open
If GitHub, the catalogue, or an installation lookup cannot be reached, the answer is a refusal or source_unavailable, never a guess.
Only public material leaves the connector
RFP briefs are curated summaries. Design resources come from an explicit allowlist of public files. Entries that are not approved for the public never appear on this site.

Deploying this site

This manual is a static page in site/, published by GitHub Pages from the BetterHackdays repository to the custom domain hack.knowb.run. It has no build step beyond rendering its reference blocks, no tracking, and no third-party scripts.

Pipeline

  1. Checkbuild_site.py --check

    On every pull request, the docs test confirms the reference blocks match the code.

  2. Build.github/workflows/pages.yml

    On a push to main that touches the site or the connector, the workflow checks the page again and uploads site/.

  3. Servehack.knowb.run

    GitHub Pages serves the artifact over HTTPS with a certificate it issues for the custom domain.

Custom domain setup

Done once, by a repository admin and the owner of the knowb.run DNS zone.

  1. Enable Pages from Actions. Repository settings, Pages, Source: GitHub Actions. Or: 
    gh api -X POST repos/knowb-ai/BetterHackdays/pages -f build_type=workflow
  2. Add the DNS record at the knowb.run DNS host:
    TypeHostAnswer
    CNAMEhackknowb-ai.github.io
  3. Set the custom domain. Pages deployed by Actions ignore a CNAME file, so set it in settings or with: 
    gh api -X PUT repos/knowb-ai/BetterHackdays/pages -f cname=hack.knowb.run
    site/CNAME is kept in the repository as a record of the intended domain.
  4. Enforce HTTPS once GitHub has issued the certificate, usually within an hour of DNS resolving: 
    gh api -X PUT repos/knowb-ai/BetterHackdays/pages -F https_enforced=true
  5. Verify the domain for the knowb-ai organization under organization settings, Pages, so no other account can claim hack.knowb.run.

Verify a deployment

dig +short hack.knowb.run CNAME      # knowb-ai.github.io.
curl -sI https://hack.knowb.run | head -1   # HTTP/2 200
gh api repos/knowb-ai/BetterHackdays/pages --jq '.cname, .https_enforced, .status'

Local preview: python -m http.server -d site 8080, then open http://localhost:8080.

FAQ

Do I need permission to read RFPs?

No. Listing, searching, reading, and comparing RFPs, reading design resources, and qualifying ideas need no account and no token.

I submitted an access request. Can I push now?

No. A request is not a grant. A repository owner reviews it, and only their explicit approval, sent as a GitHub invitation, gives you access.

Why does my submit say unauthorized?

The connector could not verify you. Check that GITHUB_TOKEN belongs to your own account and is current, and that your account has the permission the request type needs on BetterHackdays. Work elevation needs write or higher.

My submit came back “not sent”. Is that an error?

It means mail is not configured where the server runs. You get the full addressed draft so you can send it to ping@knowb.run yourself. The request is still recorded locally.

Why is the idea catalogue not on this site?

It has one home, Cloud Builder Stack, so it never drifts. The connector reads it live, and this page links to it.

Can I host my own connector?

Yes. It is a FastAPI app and a FastMCP server. Run it locally as shown in the quickstart, or anywhere Python runs. Requests still go to KnowB maintainers for review.

Contributing

BetterHackdays is developed in the open at knowb-ai/BetterHackdays. Issues and small, reviewable pull requests are welcome.

  • Run the test suite before you open a pull request: .venv/bin/python -m unittest discover -s tests -v.
  • If you change README.md, agents.md, or docs/*.md, update their OKF checksums and run python scripts/validate_okf.py.
  • If you change the connector's tools or routes, run python scripts/build_site.py so this manual stays in step.
  • Use conventional commit prefixes: feat:, fix:, chore:.
  • Read agents.md if an agent is working with you.
